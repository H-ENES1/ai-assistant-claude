WHAT'S MISSING

Claude Code shows your usage. The chat screen doesn't.

On claude.ai you have to open Settings → Usage, and it only tells you what you've already used. Limits often run out in the middle of a task, on a message you didn't expect. Token Forecast brings this into the chat and goes one step further: before you send.

HOW IT WORKS

Less like a price list, more like a measuring instrument.

Anthropic doesn't publish exact limit sizes. So the extension starts from a rough prior and corrects itself on every message by measuring how your real usage percentage changes before and after.

maliyet = w_model × [ yeni girdi + önbellekte olmayan geçmiş + araç girdisi + 5 × (cevap + düşünme) ] limit % = k × maliyet
w_model
The model's relative price. The gap between Haiku, Sonnet, Opus and Fable shows up in your limit at the same ratio (an assumption, corrected by measurement).
history
A chat used within the last hour is read from cache and doesn't count against your limit. Wait an hour and the whole history counts again; the extension warns you.
reply
Reply length comes from a distribution per task type (CASTILLO dataset, 12 task types). That's why you see an 80% range, not a single number.
5 ×
Output tokens cost five times input tokens. Thinking (effort) tokens are invisible but they count.
k
“What percentage of my limit is one cost unit?” Specific to your plan. Learned after every message with a Gamma-Poisson update; tracked separately for peak hours.

MODEL SUGGESTION

Not the lightest model. The lightest model that's enough.

Suggesting a light model is a worse mistake than suggesting an expensive one: a bad answer means asking again. The extension suggests Haiku only for clearly simple tasks it's confident about; when unsure it says at least Sonnet. Its basis is Anthropic's model selection guide, a 60-prompt suggestion test set (100% fit, zero too-light suggestions) and the on-device learned model.

0.25×vs Sonnet

2×vs Sonnet

When difficulty cues (prove, architecture, comprehensive…) are high.

Fable 5.2

Only for very hard derivations, designs and research.

Relative cost: assumed proportional to API price and corrected by calibration. On claude.ai the system prompt and memory push the context above 100K tokens, so Haiku's long-context price applies. Switching models in a long chat means the new model re-reads the whole history; in that case the extension says “pick it in your next new chat”.

TOPIC AND EFFORT

Same question, different topic: different model, different effort.

A second axis next to the task type: it sorts a message into 16 topic areas and sub-topics (on your device, by keywords). For health, law and money questions it never suggests a light model and keeps effort at Medium or above. In science, math and engineering it raises effort one level for explanations. In poetry and fiction it caps effort at Medium, because long thinking adds little there.

MACHINE LEARNING

Rules start it, a model learns, you correct it.

Knowing what kind of task a message is underpins both the estimate and the model suggestion. The old version recognized it with rules only. Now the rule scores feed a small learned model that runs on your device. The model is 128 KB, never goes online and runs within a keystroke.

64%→88%

Task type recognized correctly: rules → rules + model. On 120 everyday messages written without looking (no diacritics, greetings, typos).

16→4

Dangerous errors: taking a hard task (code, math, research) for a simple one. Two test sets, 240 messages.

32→66/80

Correct Haiku suggestions on truly simple tasks. Wrong Haiku suggestions 0 → 1 (“17% of 2350”).

  1. Personal calibrationFrom your limit percentage read before and after every message, it learns your plan's size, the peak-hour effect and the answer lengths Claude gives you.
  2. Personal correctionsWhen you say “wrong task type?” in the suggestion and pick the right one, the model updates on your device; 👍/👎 tune the suggestion bounds. What's stored is weight differences, not text.
  3. Community (optional)If you share a text-free summary of what was learned, new users start from real measurements instead of guesses.

Honest note: the training and test messages were also written by the project; accuracy on real user messages hasn't been measured yet. That's exactly what community contributions are for. Answer quality (was Haiku really enough?) wasn't measured.

PROOF

Does it learn over time? We measured.

200 simulated users with hidden true values (120 messages each), running the extension's real forecast and calibration code. Each message is forecast first, then the truth is seen and learned. A copy that doesn't learn and a perfect forecaster that knows the true values run on the same message stream.

2.04× → 1.40×

Block-total error: first 3 messages → last 40 messages. The copy that doesn't learn stays around 2.1–2.2×.

≈ 79%

The 80% forecast range covers the truth about 79% of the time (target 80%). The ranges are neither too narrow nor too wide.

1.74× / 1.71×

Single-message error: learning / perfect forecaster floor. The remaining error is the randomness of reply length; learning can't fix it.

What this does not prove

  • The users are simulated. Real accounts may differ, which is why the report's “Proof of learning” section checks you against your own measurements.
  • The spend of one message can't be known in advance: reply length and hidden thinking are random. The learning forecast comes down to this randomness floor (1.7×) and can't go below it. The goal is to keep the total and the range right.
  • For task recognition, personal corrections did not give a measurable accuracy gain on 240 varied messages (it stayed around 90%). Corrections are for fixing your own recurring patterns, they don't raise general accuracy.
  • The experiments are reproducible: tests/learning-proof.mjs and tests/classifier-learning.mjs.

NATURE

Not wasting compute is the easiest saving.

Every Claude answer is made in data centers that use electricity, and water for cooling. Picking the strongest model and the highest effort for a simple task means more compute than needed. In our tests, following the suggestions cut compute by ≈ 40%.

≈ 40%

Less compute when following the suggestions, across 240 sample messages (between 38% and 50%).

10–50 MWh

Energy saved per week if 1 million people sent 100 messages each. A week of electricity for hundreds of homes.

35–250 tons

Water saved per week in the same scenario. 100 tons is a day's drinking water for 50,000 people.

These are estimates. We assumed an answer of ≈ 400 tokens per message, 0.6–3 mWh of energy per token (0.24–1.2 Wh per message) and 3.6–5.3 L of water per kWh (≈ 0.9–6 mL per message; data center cooling plus power generation). Sources: Epoch AI 2025, Jegham et al. 2025, Li et al. 2023, Google's Gemini measurement (August 2025: median prompt 0.24 Wh). Long messages with thinking use more. Anthropic doesn't publish these figures for Claude. For one person: ≈ 10–50 Wh a week, enough to run a 9 W LED bulb for 1–5 hours.

PRIVACY

Everything is computed in your browser.

The extension has no server. Your messages, attachments and chats never leave your device; no analytics, no tracking. It only runs on claude.ai, with your own session.

What it reads, and why

  • claude.ai's usage page data: your 5-hour and weekly percentage.
  • The open chat's history length: for cache and context math (text is counted locally).
  • The text and attachments in the message box: only to count tokens, locally.
  • Permissions: storage, alarms, notifications, and only the claude.ai site.

INSTALL

Installs in two minutes.

Install it in one click from the Chrome Web Store; Edge and Brave can use the same page, and Opera works with the “Install Chrome Extensions” add-on. If you'd rather install it by hand, the steps are below.

Add to Chrome · free

  1. Download the release zip: download page.
  2. Right-click the zip → Extract all. You get a folder with manifest.json directly inside.
  3. Go to chrome://extensions (Opera: opera://extensions) and turn on Developer mode.
  4. Load unpacked → choose the extracted folder.
  5. Reload your claude.ai tab. A pill appears above the message box; start typing.

Don't lose what it learned when updating

Before removing the old version, open the extension window: Settings → Export my data. After installing the new one, use Import my data.

If something doesn't work

Health check in the window shows the state of every step. Use Copy log when reporting a bug; the log contains no message text.

LIMITATIONS

We also tell you what we don't know.

  • It relies on claude.ai's undocumented internals. If Anthropic changes the page, an update is needed; the health check shows it right away.
  • Ranges are wide for the first messages; limit sizes start as rough estimates.
  • Model suggestions come from rules plus a small learned model; answer quality was not measured. Your 👍/👎 and task-type corrections tune them to you.
  • During peak hours (weekdays 05:00–11:00 Pacific) the 5-hour limit fills faster; Anthropic hasn't published the multiplier, so the extension learns it by measuring.
  • Using the same account on another device or in Claude Code at the same time can disturb measurements; the outlier filter removes most of them.
  • Topic recognition is keyword-based. On a nearly blind set of 90 messages written after the rules were finished, it found 71% with 1 wrong area; when it can't find one it says “General” and the suggestion doesn't change. Whether the suggested effort preserves answer quality has not been measured.
  • Thinking tokens are never visible on claude.ai; they're only learned indirectly from usage changes.
  • The interface comes in 10 languages, but message analysis (task type, topic, model and effort suggestions) currently works only for Turkish and English messages. In other languages you still get the token and limit forecast (the token count is tuned per language, though measured on fewer samples), but no suggestions.

FAQ

Things you might wonder.

What is the Claude usage limit (rate limit), and when does it reset?

claude.ai has two limits: a 5-hour session limit and a weekly limit. Anthropic doesn’t publish their exact size; Settings → Usage shows how much you’ve used and when it resets. Token Forecast shows the same percentage inside the chat and estimates how much of it a message will use before you send it.

Does it work as a Claude token counter?

Yes. It counts the tokens of your message, attachments and chat history in your browser; in the demo above you see them in the “INPUT → REPLY” row. Claude’s tokenizer isn’t public, so the count is an estimate, tuned per language. Its real job is telling you what share of your limit those tokens are.

Does it cost anything?

No. You don't need an account either.

Does it read my messages and send them somewhere?

It reads the message box in your browser to count tokens, but sends nothing anywhere. The extension has no server, no analytics, no tracking. The weekly report and learned values contain no message text.

How accurate are the estimates?

Ranges are wide for the first messages because limit sizes start as rough guesses. It narrows by measuring every message; in simulation the error drops to 1.13× after 20 messages and 1.08× after 100. The window shows how many measurements fell inside the range.

How is it different from Claude's own usage screen?

Settings → Usage shows what you've already used. Token Forecast tells you, before you send, how much this message will use, which model is enough, and why something cost so much.

Could it harm my account?

It isn't an official Anthropic tool. It reads the usage data claude.ai's own pages use, with your session; it never sends messages, changes settings or automates anything.

Which browsers?

Chrome, Opera, Edge and Brave (Chromium 116 or later). A Firefox version is on the roadmap.

Is the source code open?

Yes. The code is open under the GNU AGPL-3.0: you can read, run, modify and share it. If you distribute a modified version, you must release it under the same license with its source code and keep the copyright notice. The name and logo “Token Tahmini / Token Forecast” are not covered by the license; modified versions must use a different name.

Why doesn't it suggest Haiku when my message contains “translate”?

It looks at the task, not the word. “Translate this: …” is a translation request and Haiku is enough. “I need a site with a translation system built” is a build job and at least Sonnet is suggested. 15 such trap sentences and real translation requests are in the automated tests.

How do I see that it really learns?

Extension window → Weekly report → Proof of learning. After 30 measurements it compares the error of the first and the latest measurements, and says so if it did not drop. The experiment we ran with simulated users is in the Proof section above.

Which languages does it work in?

The extension and this site come in Turkish, English, German, French, Spanish, Italian, Portuguese, Russian, Japanese and Chinese; pick one in the settings. Message analysis (task type, topic, model and effort suggestions) is done only for Turkish and English messages. If you write in another language, the token and limit forecast still works, no suggestion is shown and the extension tells you so. The intro video and screenshots are in Turkish and English; the other languages see the English ones.
