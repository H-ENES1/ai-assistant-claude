在你消耗额度之前、之中和之后。

之前

带理由的模型建议

之前

成本拆分新

之前

之中

消息数、已用额度、高峰时段占比、模型和任务构成、按小时热力图，以及为你量身定制的建议。周一早晨提醒，可导出 CSV。

工作原理

与其说是价目表，不如说是测量仪器。

Anthropic 不公布额度的确切大小。因此扩展从粗略估算起步，并在每条消息之后，通过测量你的真实用量百分比在前后如何变化来修正自己。

maliyet = w_model × [ yeni girdi + önbellekte olmayan geçmiş + araç girdisi + 5 × (cevap + düşünme) ] limit % = k × maliyet
w_model
模型的相对价格。Haiku、Sonnet、Opus 和 Fable 之间的差异会按相同比例反映到你的额度上（这是一个假设，会被测量值修正）。
历史
最近一小时内用过的聊天会从缓存读取，不计入你的额度。等上一小时，整个历史又会重新计入；扩展会提醒你。
回复
回复长度来自按任务类型划分的分布（CASTILLO 数据集，12 种任务类型）。所以你看到的是 80% 区间，而不是一个单一数字。
5 ×
输出 token 的成本是输入 token 的五倍。推理（强度）token 看不见，但会计入。
k
“一个成本单位占我额度的多少百分比？”取决于你的套餐。每条消息后用伽马-泊松更新来学习；高峰时段单独记录。

模型建议

不是最轻的模型，而是够用的最轻的模型。

建议轻量模型比建议昂贵模型错得更严重：差的回复意味着再问一次。扩展只对明显简单、且有把握的任务建议 Haiku；拿不准时至少说 Sonnet。依据是 Anthropic 的模型选择指南、一个 60 条提示词的测试集（100% 合适，没有过轻的建议）以及设备上学习的模型。

Haiku 5.5

0.25×相对于 Sonnet

延迟和价格最低。翻译、校对、简短摘要、单一答案的问题。

仅对明显简单且有把握的任务建议。

Sonnet 5.5

1×相对于 Sonnet

适合日常工作的速度与能力：代码、数据分析、写作、讲解。

大多数任务的默认建议；拿不准时的稳妥选择。

Opus 5.5

2×相对于 Sonnet

复杂编程和企业级任务：大型重构、系统设计、长时间的智能体运行。

当难度线索（证明、架构、详尽…）很强时。

Fable 5.2

5×相对于 Sonnet

最强能力：持续数小时的智能体会话、多步骤的深度研究。

仅用于非常困难的推导、设计和研究。

相对成本：假设与 API 价格成正比，并由校准修正。在 claude.ai 上，系统提示词和记忆会让上下文超过 10 万 token，因此适用 Haiku 的长上下文价格。在长聊天里换模型意味着新模型要重读整个历史；这时扩展会说“请在下一个新对话中选择”。

主题与强度

同一个问题，不同主题：不同模型，不同强度。

任务类型之外的第二个维度：把消息归入 16 个主题领域和子主题（在你的设备上，通过关键词）。对健康、法律和金钱的问题，绝不建议轻量模型，并将强度保持在“中”或以上。在科学、数学和工程的讲解中，把强度提高一级。在诗歌和小说中，把强度限制在“中”，因为长时间思考在那里收益不大。

机器学习

规则起步，模型学习，你来纠正。

知道一条消息属于哪种任务，是估算和模型建议的基础。旧版本只用规则识别。现在规则的得分会输入一个在你设备上运行的小型学习模型。模型只有 128 KB，从不联网，运行时间比一次按键还短。

64%→88%

任务类型识别正确率：规则 → 规则 + 模型。基于 120 条不看样本写出的日常消息（无重音符号，带问候语和错别字）。

16→4

危险错误：把困难任务（代码、数学、研究）当成简单任务。两个测试集，共 240 条消息。

32→66/80

真正简单的任务上 Haiku 建议正确的次数。Haiku 错误建议 0 → 1（“2350 的 17%”）。

  1. 个人校准根据每条消息前后读到的额度百分比，学习你的套餐大小、高峰时段的影响，以及 Claude 给你的回复长度。
  2. 个人纠正当你在建议中点“任务类型不对？”并选出正确类型时，模型会在你的设备上更新；👍/👎 会调整建议的阈值。保存的是权重差，而不是文本。
  3. 社区（可选）如果你分享一份不含文本的学习摘要，新用户就能从真实测量值起步，而不是靠猜测。

坦白说明：训练和测试用的消息也是项目自己写的；在真实用户消息上的准确率尚未测量。这正是需要社区贡献的原因。回复质量（Haiku 真的够用吗？）没有测量。

证明

它会随时间学习吗？我们测量过。

200 个隐藏了真实值的模拟用户（各 120 条消息），运行扩展真正的预测和校准代码。每条消息先预测，再看到真实值并学习。一个不学习的副本和一个知道真实值的完美预测器，在同样的消息流上运行。

2.04 倍 → 1.40 倍

区块总量误差：最初 3 条消息 → 最后 40 条消息。不学习的副本一直在 2.1–2.2 倍左右。

≈ 79%

80% 预测区间约 79% 的情况下包含真实值（目标 80%）。区间既不太窄也不太宽。

1.74 倍 / 1.71 倍

单条消息误差：会学习的 / 完美预测器的下限。剩下的误差是回复长度的随机性；学习无法修正。

这不能证明什么

  • 用户是模拟的。真实账号可能不同，所以报告中的“学习证明”一节会用你自己的测量来检验你。
  • 单条消息的消耗无法事先知道：回复长度和隐藏的推理都是随机的。会学习的预测会下降到这个随机性下限（1.7 倍），不能再低。目标是命中总量和区间。
  • 在任务识别上，个人纠正在 240 条各异的消息上没有带来可测量的准确率提升（仍在 90% 左右）。纠正用来修正你反复出现的模式，并不提高整体准确率。
  • 实验可复现：tests/learning-proof.mjs 和 tests/classifier-learning.mjs。

自然

不浪费算力，是最简单的节约。

Claude 的每个回答都在数据中心生成，这些数据中心耗电，并用水来冷却。为简单任务选择最强的模型和最高的思考强度，意味着使用了超出需要的算力。在我们的测试中，遵循建议后算力减少了约 40%。

≈ 40%

遵循建议后减少的算力（240 条示例消息，介于 38% 到 50% 之间）。

10–50 MWh

如果 100 万人每人发送 100 条消息，每周节省的能源。相当于数百户家庭一周的用电量。

35–250 吨

同一情景下每周节省的水。100 吨是 5 万人一天的饮用水。

这些都是估算。我们假设每条消息的回答约 400 个 token，每个 token 消耗 0.6–3 mWh 能源（每条消息 0.24–1.2 Wh），每 kWh 用水 3.6–5.3 L（每条消息约 0.9–6 mL；数据中心冷却加发电）。来源：Epoch AI 2025、Jegham et al. 2025、Li et al. 2023、Google 的 Gemini 测量（2025 年 8 月：中位数提示 0.24 Wh）。带思考的长消息消耗更多。Anthropic 未公布 Claude 的这些数据。对一个人来说：每周约 10–50 Wh，足以让一盏 9 W 的 LED 灯亮 1–5 小时。

社区

一起变得更准。

Anthropic 不公布额度大小；每位用户通过测量来学习自己的套餐。把这些测量汇总起来，新用户从第一条消息起就能得到准确估算。不会自动发送任何内容。

如何参与

  1. 在扩展窗口中：参与社区贡献 → 显示贡献摘要。里面只有数字和标签。
  2. 复制并打开表单，粘贴到表单中并提交。
  3. 摘要会被合并；下一个版本会为所有人带来更好的初始值。

贡献表单 · 2 分钟问卷

隐私

一切都在你的浏览器里计算。

扩展没有服务器。你的消息、附件和聊天从不离开你的设备；没有分析，也没有追踪。它只在 claude.ai 上运行，使用你自己的会话。

它读取什么，为什么

  • claude.ai 用量页面的数据：你的 5 小时和每周百分比。
  • 已打开聊天历史的长度：用于缓存和上下文计算（文本在本地统计）。
  • 消息输入框中的文本和附件：仅用于在本地统计 token。
  • 权限：存储、闹钟、通知，以及仅限 claude.ai 站点。

安装

两分钟即可安装。

在 Chrome 网上应用店一键安装；Edge 和 Brave 可使用同一页面，Opera 需借助“Install Chrome Extensions”扩展。如果想手动安装，步骤见下方。

添加到 Chrome · 免费

  1. 下载发布版 zip：下载页面。
  2. 右键点击 zip → 全部解压。得到的文件夹里直接就是 manifest.json。
  3. 打开 chrome://extensions（Opera：opera://extensions），打开开发者模式。
  4. 加载已解压的扩展程序 → 选择解压出来的文件夹。
  5. 刷新你的 claude.ai 标签页。消息输入框上方会出现一个药丸；开始输入吧。

更新时别丢掉它学到的内容

删除旧版本之前，先打开扩展窗口：设置 → 导出我的数据。安装新版本后，使用导入我的数据。

如果有什么不工作

窗口中的系统检查会显示每一步的状态。报告问题时请使用复制日志；日志不含消息文本。

局限

我们也会告诉你我们不知道的事。

  • 依赖 claude.ai 未公开文档的内部实现。如果 Anthropic 改动页面，就需要更新；系统检查会立刻显示出来。
  • 最初几条消息的区间较宽；额度大小从粗略估算起步。
  • 模型建议来自规则加一个小型学习模型；回复质量没有测量。你的 👍/👎 和任务类型纠正会让它适应你。
  • 在高峰时段（工作日太平洋时间 05:00–11:00），5 小时额度消耗更快；Anthropic 没有公布倍数，所以扩展通过测量来学习。
  • 同一账号同时在另一台设备或 Claude Code 中使用，可能干扰测量；异常值过滤会去掉大部分。
  • 主题识别基于关键词。在规则写完后新写的 90 条近乎盲测的消息上，找到了 71%，其中 1 个领域有误；找不到时，会显示“通用”，建议不变。建议的强度是否能保持回复质量，没有测量。
  • 推理 token 在 claude.ai 上永远看不到；只能从用量变化中间接学到。
  • 界面有 10 种语言，但消息分析（任务类型、主题、模型和强度建议）目前只支持土耳其语和英语消息。用其他语言时，你仍然能得到 token 和额度预测（token 统计已按语言调整，但测量样本较少），只是没有建议。

常见问题

你可能想问的。

Claude 的使用限额是什么？什么时候重置？

claude.ai 有两种限额：5 小时会话限额和每周限额。Anthropic 没有公布它们的具体大小；“设置 → 用量”会显示你已经用了多少、何时重置。Token Forecast 在对话中显示同样的百分比，并在发送之前估算一条消息会用掉其中多少。

它能当作 Claude 的 token 计数器用吗？

可以。它在你的浏览器里统计消息、附件和聊天记录的 token 数；在上面的演示中显示在“输入 → 回复”一行。Claude 的分词器没有公开，所以这个数字是按语言调校过的估算值。它真正的作用是告诉你这些 token 占你限额的多少。

要花钱吗？

不要。也不需要账号。

它会读取我的消息并发送到别处吗？

它会读取你浏览器中的消息输入框来统计 token，但不会把任何内容发送到任何地方。扩展没有服务器，没有分析，也没有追踪。每周报告和学到的数值都不含消息文本。

估算有多准？

最初几条消息的区间较宽，因为额度大小是从粗略猜测起步的。每测量一条消息就会收窄；在模拟中，误差在 20 条消息后降到 1.13 倍，100 条后降到 1.08 倍。窗口会显示有多少次测量落在区间内。

它与 Claude 自带的用量页面有什么区别？

“设置 → 用量”显示你已经用掉的部分。Token Forecast 在发送之前就告诉你这条消息将消耗多少、哪个模型够用，以及某件事为什么这么贵。

会危害我的账号吗？

它不是 Anthropic 的官方工具。它在你的会话中读取 claude.ai 页面自己使用的用量数据；从不发送消息、不更改设置，也不自动化任何操作。

支持哪些浏览器？

Chrome、Opera、Edge 和 Brave（Chromium 116 或更高版本）。Firefox 版本在路线图中。

源代码是开源的吗？

是的。代码以 GNU AGPL-3.0 许可证开源：你可以阅读、运行、修改和分享。如果你分发修改后的版本，必须以相同许可证连同源代码一起发布，并保留版权声明。名称和徽标“Token Tahmini / Token Forecast”不在许可证范围内；修改后的版本必须使用其他名称。

我的消息里有“翻译”，为什么不建议 Haiku？

看任务，而不是看字眼。“翻译这段：…”是翻译请求，Haiku 就够了。“我需要一个带翻译系统的网站”是搭建工作，至少会建议 Sonnet。自动化测试里有 15 个这样的陷阱句子和真正的翻译请求。

我怎么看出它真的在学习？

扩展窗口 → 每周报告 → 学习证明。测量 30 次后，它会比较最初和最近几次测量的误差，如果没有下降就会说明。模拟用户的实验在上面的“证明”一节。

它支持哪些语言？

扩展和本网站提供土耳其语、英语、德语、法语、西班牙语、意大利语、葡萄牙语、俄语、日语和中文；语言可在设置中选择。消息分析（任务类型、主题、模型和强度建议）只针对土耳其语和英语消息进行。如果你用其他语言书写，token 和额度预测仍然有效，但不会显示任何建议，扩展会告诉你这一点。介绍视频和截图有土耳其语和英语版本；其他语言显示英语版本。
